## 不同问题，后台发生了什么？

**简单日常问题**（比如"今天天气怎样"、"帮我翻译一句话"）

基本上是直接从训练权重里"召回"答案，不需要复杂的推理链。模型在 forward pass 里快速完成，token 生成速度快，延迟低。如果问题涉及实时信息（天气、新闻），系统会先触发工具调用（搜索、天气 API），再把结果拼入 context 生成回答。

**算法问题**（比如"写一个快速排序"）

模型会在生成过程中隐式地做"思维展开"——把问题分解成：理解需求 → 选择算法策略 → 逐步生成代码。这不是显式的多步规划，而是 Transformer 在深层注意力机制里完成的。对于需要验证的场景，像我这样有代码执行工具的配置，会实际跑一遍代码验证结果。

**复杂推理 / 编码逻辑**（比如"帮我设计一个分布式系统"）

这里差异最大。Anthropic 对 Claude 3.x/4.x 系列引入了**扩展思考（Extended Thinking）**机制——模型在正式输出前，会有一段内部的 `<thinking>` 过程，类似草稿纸，用来分解子问题、自我纠错、权衡方案。这段思考对用户可见或不可见取决于产品配置。本质上是让模型用更多计算 token 换取更高质量的输出。

---

## 一个简化的示意

```
用户输入
   │
   ├─ 意图分类（需要工具？需要深度推理？）
   │
   ├─ 简单 → 直接生成（1次 forward pass）
   │
   ├─ 需要工具 → 工具调用 → 结果注入 context → 生成
   │
   └─ 复杂推理 → [Extended Thinking] → 生成最终回答
```

---

## 几个关键点

- **没有真正的"路由器"**：并不存在一个独立模块判断"这题难不难"，而是模型本身在训练中学会了分配计算资源的方式。
- **上下文窗口是核心**：所有工具结果、历史对话都会被压进同一个 context window，模型统一处理。
- **推理成本不同**：简单问题便宜，复杂推理贵——这也是为什么 API 定价会区分 input/output token，以及思考 token 单独计费。

本质上，"路由"更多是**涌现行为**，而不是硬编码的规则系统。

**几个值得延伸的点：**

第一层"入口分诊"这个说法，在 Anthropic 这边我自己的感知是——**没有独立的分类器**，更像是 system prompt + 模型本身的 in-context 判断，而 Google 那种显式用小模型分流是更工程化的做法，两种架构哲学不同。

第二层安全层，Anthropic 公开得相对多，Constitutional AI 和后来的 RLHF/RLAIF 让"拒绝判断"被烘焙进权重，而不只是一个独立 guard model 在前面拦截，这两种做法的失败模式也不同。

第五层工具循环，这里有个关键细节：**工具调用结果会作为新的 context 追加进去，模型重新 attend 整个上下文**，所以多轮工具调用的成本是 O(n²) 级别增长的，这也是为什么 token 成本控制是 agentic 产品的核心工程问题。

几个补充 GPT 没有展开的地方：

**⑤ 的循环代价是核心工程难题。** 每次工具调用返回后，结果会追加进 context，模型对整个上下文重新做 attention。这意味着随着循环次数增加，计算量大致按 O(n²) 增长——这是为什么 agentic 场景的 token 成本会比普通对话贵得多，也是为什么 OpenAI/Anthropic 都在做 "context cache" 优化。

**① 的"分诊"在 Anthropic 这边更多是涌现行为而非硬路由。** Google Gemini 那边用小模型先分流再交给大模型处理的做法更偏工程化，两种路线的 tradeoff 是延迟 vs 灵活性。

**⑥ 实际上有时会有"reasoning summary"这一步**——thinking token 的内部推理过程有时会被压缩成一段可读摘要给用户，而不是直接暴露原始思维链，这一层属于展示层和执行层的解耦。
