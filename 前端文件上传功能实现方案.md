## 前端文件上传完整方案

---

### 一、交互层

**选择多个文件**

用 `<input type="file" multiple>` 即可，用户可框选多文件。触发后从 `input.files`（FileList 对象）拿到所有文件。

**选择文件夹**

加上 `webkitdirectory` 属性，浏览器会递归把整个文件夹的文件都塞进 FileList，同时每个 File 对象上有 `file.webkitRelativePath` 保留目录结构（如 `folder/sub/a.txt`）。

```html
<input type="file" multiple />                  <!-- 多文件 -->
<input type="file" webkitdirectory />           <!-- 文件夹 -->
```

**拖拽文件和文件夹**

监听 drop 区域的 `dragover` / `drop` 事件。关键在于 drop 事件里用 **DataTransfer API** 处理两种情况：

```js
dropZone.addEventListener('drop', async (e) => {
  e.preventDefault();
  const items = [...e.dataTransfer.items];
  const files = [];

  for (const item of items) {
    const entry = item.webkitGetAsEntry();       // 获取 FileSystemEntry
    if (entry.isFile) {
      files.push(await entryToFile(entry));
    } else if (entry.isDirectory) {
      await traverseDirectory(entry, files);     // 递归遍历目录
    }
  }
  // files 即为最终文件列表
});

async function traverseDirectory(dirEntry, result) {
  const reader = dirEntry.createReader();
  const entries = await new Promise(res => reader.readEntries(res));
  for (const entry of entries) {
    if (entry.isFile) result.push(await entryToFile(entry));
    else await traverseDirectory(entry, result); // 递归
  }
}
```

### 二、网络层

#### 架构选型

| 场景 | 方案 |
|---|---|
| 小文件（< 5MB） | 单个 XHR/fetch 直传 |
| 大文件（> 5MB） | **分片上传（Multipart）** |
| 极大文件 | 分片 + 秒传（MD5 校验） |

阿里云 OSS 的核心就是**分片上传**，下面重点展开。

---

#### 分片上传流程

```
┌─────────────┐     1. 初始化上传      ┌─────────────┐
│   Browser   │ ──────────────────────▶ │   Server    │
│             │ ◀────────────────────── │  /OSS       │
│             │     返回 uploadId        │             │
│             │                         │             │
│             │  2. 并发上传各分片       │             │
│             │ ──────────────────────▶ │             │
│             │  chunk1, chunk2, ...     │             │
│             │ ◀────────────────────── │             │
│             │     返回各片 ETag        │             │
│             │                         │             │
│             │  3. 合并分片             │             │
│             │ ──────────────────────▶ │             │
└─────────────┘                         └─────────────┘
```

#### 核心代码实现

```js
const CHUNK_SIZE = 5 * 1024 * 1024; // 5MB 每片
const MAX_CONCURRENT = 3;           // 最大并发数

async function uploadFile(file) {
  // 1. 切片
  const chunks = sliceFile(file);
  
  // 2. 初始化（向服务端拿 uploadId）
  const { uploadId } = await initUpload(file.name);

  // 3. 并发上传（控制并发数）
  const etags = await uploadChunks(chunks, uploadId);

  // 4. 合并
  await mergeChunks(uploadId, etags, file.name);
}

function sliceFile(file) {
  const chunks = [];
  let start = 0, index = 0;
  while (start < file.size) {
    chunks.push({ blob: file.slice(start, start + CHUNK_SIZE), index });
    start += CHUNK_SIZE;
    index++;
  }
  return chunks;
}
```

#### 进度追踪

XHR 的 `upload.onprogress` 只能追踪**单个请求**的进度，多片并发时要聚合每片进度：

```js
// 每个分片维护独立进度
const chunkProgress = new Array(chunks.length).fill(0);

function uploadChunk(chunk, uploadId) {
  return new Promise((resolve, reject) => {
    const xhr = new XMLHttpRequest();
    xhrMap.set(chunk.index, xhr);               // 存起来，用于取消

    xhr.upload.onprogress = (e) => {
      chunkProgress[chunk.index] = e.loaded;    // 更新该片已传字节数
      const total = chunkProgress.reduce((a, b) => a + b, 0);
      const percent = (total / file.size * 100).toFixed(1);
      onProgress(percent);                       // 回调更新 UI
    };

    xhr.open('PUT', `/upload/chunk?id=${uploadId}&index=${chunk.index}`);
    xhr.onload = () => resolve(xhr.getResponseHeader('ETag'));
    xhr.onerror = reject;
    xhr.send(chunk.blob);
  });
}
```

#### 取消上传

```js
const xhrMap = new Map();  // index -> XHR 实例

function cancelUpload() {
  for (const xhr of xhrMap.values()) {
    xhr.abort();           // 逐一中断所有正在传的分片请求
  }
  xhrMap.clear();
  // 通知服务端清理未完成的 uploadId（可选）
  abortUpload(uploadId);
}
```

如果用 `fetch`，则用 `AbortController`：

```js
const controller = new AbortController();
fetch(url, { signal: controller.signal, body: chunk });

// 取消时：
controller.abort();
```

### 三、进阶能力（阿里云同款）

**秒传**：上传前先用 `spark-md5` 计算文件 MD5，发给服务端查重，命中则直接返回 URL，无需真正上传。

**断点续传**：把已上传的分片 index 存入 localStorage，刷新后跳过已完成的分片继续传。

**并发控制**：用 `p-limit` 或手写信号量，避免同时发几十个请求打爆带宽或触发服务端限流。

```js
// 手写并发池
async function uploadChunks(chunks, uploadId) {
  const results = [];
  const queue = [...chunks];
  const workers = Array(MAX_CONCURRENT).fill(null).map(async () => {
    while (queue.length) {
      const chunk = queue.shift();
      results[chunk.index] = await uploadChunk(chunk, uploadId);
    }
  });
  await Promise.all(workers);
  return results;
}
```

### 四、总结

```
用户操作
  ├── input[multiple]        → FileList
  ├── input[webkitdirectory] → FileList（含路径）
  └── drag & drop            → DataTransfer + FileSystemEntry API（递归遍历）
         ↓
文件队列（含元信息、状态、进度）
         ↓
上传引擎
  ├── 分片（slice）
  ├── MD5 → 秒传检查
  ├── 并发控制（信号量）
  ├── XHR / fetch（含进度回调）
  └── 取消（xhr.abort / AbortController）
         ↓
服务端 / OSS
  ├── 接收分片
  ├── 合并
  └── 返回最终 URL
```
